# Kryptos Research Mode

The standalone app in `kryptos-app/`, published under `/kryptos/`, now opens in a
research notebook rather than a general-purpose cracking form. Existing corpus,
architecture, manuscript and laboratory tabs remain available. No backend,
framework, language-model download or external analysis API is required.

An improvements dialog appears once per engine version per browser session and
lists the new workspace, notebook, comparison, reproduction and credibility
features. **What changed?** reopens it. Dismissal stores only a public version
string in session storage, never ciphertext, plaintext or keys.

## One workspace

1. **Source and alphabets:** select a generated PK1–PK10 reference, K1/K4, or
   custom ciphertext. Original text stays intact; normalized text and IC/entropy
   are shown separately. Build a keyed alphabet from a prefix, inspect its
   zero-based indices, or supply a complete A–Z permutation.
2. **Hypothesis notebook:** record a name, candidate plaintext, ordered
   decryption steps, keys, phases, optional per-step alphabets, method/provenance
   notes, supporting evidence, and reasons the proposal might be wrong.
3. **Reproduction and evidence:** run the method, examine each intermediate
   output, and compare generated/plaintext and re-encrypted/ciphertext positions.
   If no candidate was supplied, running an executable method fills it with the
   generated output; that is explicitly a reproducible reading, not a solution.
4. **Saved hypotheses and comparison:** save new hypotheses, load/update/delete
   existing ones, compare families and observations, align candidate readings
   using offsets or shared repeated sequences, and back up the notebook.

Each PK reference has an executable documented-construction template. They use
this repository's `verify_pk_constructions.py`, `verify_pk9_solution.py` and
`verify_pk10_solution.py` conventions. The JavaScript arithmetic is a separate
implementation, tested against all ten canonical plaintext/ciphertext pairs in
both directions. PK10 contains **21** decryption steps. The PK5/PK10 long key is
the normalized **documented PK4 plaintext**, not a fitted candidate.

Selecting another reference or importing a report asks before replacing the
unsaved draft. Changing any hypothesis input clears the previous displayed
reproduction verdict. Save/export recomputes current evidence directly from
current inputs; it does not reuse a stale Run result.

## Labels are different claims, not a confidence ladder

### Verified corpus match

The normalized **source ciphertext** is exactly a documented PK1–PK10 reference.
It is a lookup association, not a new cryptanalytic discovery or proof of an
unrelated proposed reading. One changed letter cannot earn this label. Source
recognition and hypothesis reproduction are displayed **separately**. A matched
source with the wrong proposed plaintext remains a **Research hypothesis**.

The explorer consumes `kryptos-app/paradigm.js`, generated by
`scripts/build_paradigm_catalog.py` from `kryptos/pk_submission_manifest.json`,
just like the Python and general browser solvers. This replaces drifting,
hand-maintained PK transcriptions. The existing K2/K3 browser entries are legacy
incomplete excerpts: they are labelled as such and disabled as research
references, rather than falsely presented as complete inscriptions. Researchers
can paste an authoritative complete transcription into custom mode. K1 has a
locally reproduced reference; CIA texts do not receive PK corpus badges. K4 has
no full reference plaintext or asserted cipher-family identification.

### Reproduced decryption

The recorded method and key regenerate the proposed normalized plaintext, **and**
the inverse method regenerates every normalized source ciphertext letter. No
round-trip claim is made for an empty method, a mismatching proposal, an
unexecuted step, or a failed operation.

This confirms reproducibility under the documented conventions—not independent
confirmation, authenticity, intended plaintext, a newly discovered solution, or
a successful reconstruction of the artist's original procedure. Many arbitrary
keys and bijective methods produce reproducible but meaningless readings. Both
`independent_verification` and `intended_plaintext_proven` remain false.

### Research hypothesis

A candidate without successful executable reproduction remains a hypothesis.
Manual/unimplemented methods can still be recorded, saved and reported, with
explicit failure/unexecuted status and any successfully executed partial trace.
There is no promotion based on convincing prose or a language score.

The older Verification Center's supplied-string comparison now reports only
**text equality**, not “verified round trip”; it executes no cipher method. The
legacy workbench reuses the same checked research operations instead of its
incorrect column-order implementation. The historical manuscript is labelled
as containing earlier hypotheses; it is not the current executable evidence.

## Exact conventions

Normalization retains ASCII A–Z/a–z and case folds. It drops spaces, punctuation,
digits and non-ASCII letters without Unicode expansion or transliteration.
Positions/phases count normalized letters; original source and candidate text
are preserved in reports. Ciphertext or candidate normalization can differ from
other tools' cipher-specific preparation. There is no silent text clipping.

Supported steps, applied in listed **decryption** order:

| Step | Convention |
|---|---|
| Vigenère / additive Quagmire III | Both text and key use the selected alphabet's index space; `C=P+K mod 26`. A KRYPTOS permutation gives the documented additive PK Q3 convention, not all Quagmire variants. |
| Beaufort | `C=K−P mod 26`, selected alphabet. |
| Variant Beaufort | `C=P−K mod 26`, selected alphabet. |
| Caesar | Decimal shift 0–25 in the selected alphabet. |
| Complete columnar | Row-wise rectangle, columns read by stable ASCII keyword order, duplicates tie by original index. Width must divide text length. |
| Top-right spiral | Complete rectangle, starts top-right and reads down/left/up/right. Key is decimal width. |
| Hill 3×3 | Nine keyword letters index a row-major matrix over Z/26Z, multiplied by column-vector triples. Matrix must be invertible; complete triples required. |
| Alphabet substitution | Maps standard A–Z to the selected alphabet on encryption; inverse on decryption. No key. |
| Reverse | Reverses all normalized letters; no key. |
| Unimplemented / description only | Recorded but never executed. Cannot earn reproduction. |

Repeated keys use `(letter_index + phase) % key_length`. Each step starts its own
normalized letter stream at index zero. Phases apply only to repeated-key
polyalphabetic steps. The default alphabet applies unless a step explicitly
supplies its own; exported reports store every effective step alphabet.
Re-encryption runs inverse operations in **reverse** sequence order.

No padding, inferred keys, route guessing, opaque code execution, or automatic
pipeline interpretation is performed. Complete-grid checks deliberately reject
unsupported ragged conventions. Hill inversion rejects noninvertible matrices.

## Comparison boundaries

“Explained ciphertext” is the number of position agreements when encrypting the
**proposed** plaintext with the method's inverses, divided by the larger text
length. Missing letters count against agreement; first mismatch is reported.
It is not a probability or a semantic plausibility metric. A correct inverse of
an arbitrarily generated reading will agree 100%; this alone does not choose a
cipher family. Different normalized source ciphertexts are explicitly flagged
as not directly comparable.

IC and Shannon entropy are marginal A–Z measurements, in normalized letters and
bits per letter; empty entropy / IC below two letters is not measurable. They
are diagnostic, not calibrated language tests. Family, evidence and objections
are visible side by side; no opaque automatic “winner” is selected.

The alignment compares normalized candidate plaintexts only. It does not imply
a transposition's character route. Shared 3–5-letter sequences must repeat in at
least one candidate; only the first 20 positions per sequence and 20 displayed
patterns are retained. “Align” uses first-occurrence offsets. Chance matches and
overlapping n-grams are not independent evidence.

For the exact repository K4 ciphertext, comparisons also check the repository's
clue constraints: EAST at zero-based 21, NORTHEAST at 25, BERLIN at 63, CLOCK at
69. These are fixed-position tests, not searches for those words anywhere. They
are explicitly repository-recorded constraints, not fresh external confirmation
or a claim of full K4 recovery. A candidate satisfying all four can still remain
an unverified research hypothesis.

## Reproducible exports and imports

**Current research report:** JSON schema `kryptos-research-report/v1`, with:

- Engine version and creation time; normalization and decryption-order rules.
- Original and normalized ciphertext/candidate, name and method notes.
- Ordered transformations, keys, phases and effective alphabets.
- Every executed intermediate input/output, family and arithmetic convention.
- Reconstructed ciphertext, exact position agreements and failures.
- Source catalog ID/digests/provenance when matched.
- Derived reproduction status, metrics, K4 constraints, evidence and objections.
- Explicit caveats and false independent/intended-plaintext verification flags.

Re-import restores **only validated hypothesis inputs** and re-executes them
under the current engine. Imported labels, intermediate outputs, source badges
and claimed verification cannot upgrade a hypothesis. Unknown operations are
rejected; JSON is parsed as data, never evaluated as code. Partial/unsupported
methods remain hypotheses with honest error details.

**Notebook backup:** JSON schema `kryptos-research-notebook/v1`, with versioned
hypothesis inputs, stable IDs and created/updated timestamps. It contains no
trusted derived status. Import validates the entire notebook before asking to
replace existing saved data. Unknown schemas, duplicate IDs and oversize inputs
are rejected without overwriting the draft/notebook.

## Persistence, privacy and bounds

Save/update is explicit browser-local storage under
`kryptos.research.notebook.v1`; unsaved drafts are not automatically persisted.
Up to 24 saved hypotheses are supported. A failed storage write retains the old
notebook; export the current report if browser storage is unavailable/full. A
corrupt notebook is not overwritten automatically: export its raw backup before
explicit deletion/replacement. Delete-all requires confirmation and leaves the
current unsaved draft available for export. Export backups before clearing
browser data or changing devices. There is no cloud synchronization.

Reports/notebooks include plaintext and keys. Research code makes no analysis
requests. The assembled public site retains its existing advertising loader;
third-party scripts are outside this research engine's guarantees. For sensitive
work, serve `kryptos-app/` locally or use an offline copy. Browser local storage
is not encrypted or isolated from other scripts on the same origin.

Bounds are 16,000 original/candidate characters, 8,000 normalized letters, 32
steps, 512 characters per key, phase 0–511, column keywords up to 128, spiral
width 1–256, name 120, notes/evidence/objections 4,000 each. Report/notebook import
is capped at 4 MB. Comparison shows up to 120 positions with offsets ±8,000.

Run `npm run test:research` for deterministic arithmetic/schema regressions.
`tests/browser/kryptos-research.spec.js` exercises the actual standalone app,
including catalog reproduction, explicit persistence, comparison, file reports,
forged-status rejection and K4 constraints. CI runs the Node tests before its
Playwright browser suite. No new Windows installer is produced by this feature.
