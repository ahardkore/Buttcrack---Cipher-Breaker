        Reading a report
        
        
        
          
        confidence
        A heuristic language/evidence rank score, not a probability of correctness. ≥ 0.62 crosses the engine's historical “solved” threshold; the panel calls that statistically strong, not verified. ≥ 0.86 stops fast mode; comparison mode continues within budget.
        
          
        path
        The decode chain, outermost layer first: base64 -> base16 -> xor_repeating.
        
          
        index of coincidence
        Probability that two random letters match. English ≈ 0.066, random ≈ 0.038, a transposition keeps it, a polyalphabetic cipher flattens it.
        
          
        quadgram fitness
        Log-probability per letter under the selected language's quadgram model — 258k quadgrams for English. Around −4.3 reads as language; below −6 does not.
        
          
        evidence cap
        A key that holds more secret than the ciphertext can pin down is capped below “solved”: plausible, not proven.
        
        
        
      
        
    
        
  
        

        



        
  
        
    
        
      
        
        
        What this is
        
        
        
          buttcrack is an automatic cipher breaker. Give it ciphertext and it works out what was
          used, recovers the key, and prints the plaintext — including puzzles where an encoding is wrapped
          around a cipher, or several layers deep.
        
        
        
        It runs three stages:
        
        
          
          
        1. Characterise. Length, alphabet, entropy, index of coincidence, chi-squared against
            the language model, structural tells (hex, base64, Morse, Bacon, Polybius, a Polybius grid, URL escapes).
          2. 
          
        2. Peel. Any strongly indicated encoding layer is stripped and the inside is attacked
            recursively, so base64 → hex → XOR is three easy problems rather than one hard one.
          3. 
          
        3. Attack. Each cipher has its own cryptanalysis: chi-squared column solving and
            quadgram hill climbing for Vigenère-family, coset-IC key-length detection plus per-byte solving for
            repeating-key XOR, simulated annealing and cycle walking for transpositions, an evidence-capped
            substitution solver.
          4. 
        
        
        
        
          Scoring uses the model picked by the Language dropdown: six languages ship in the box. English is the
          deepest — quadgram statistics from a 25-million-word corpus plus an
          80,000-word dictionary for word coverage, blended differently on short texts where quadgrams are
          unreliable. French, German, Italian, Latin and Spanish judge on their own quadgram tables, each with
          fitness thresholds measured for that language. Auto-detect probes all six and commits the
          budget to whichever reads the text best.
        
        

        
        What it will not do
        
        
        
          Modern cryptography is not a puzzle you can read your way out of. AES with a proper key, RSA, ChaCha20,
          elliptic curves: these have no letter statistics, no periodicity and no structure left to exploit, and
          brute force against a 128-bit key is not a matter of time. If your ciphertext is one of those, the honest
          answer is “this is not a classical cipher” — and that is what the detector will say.
        
        
        
        What it is genuinely good at:
        
        
          
          
        • Classical ciphers — Caesar, Vigenère and its variants, autokey, transpositions, Playfair, Bifid,
            substitution with a mixed alphabet.
          • 
          
        • Wheel ciphers — the US Army M-94 / Navy CSP-488: 25 mixed-alphabet wheels, hill-climbed over the
            25! spindle orders. Wants 200+ letters and a generous budget.
          • 
          
        • The ratchet — two mixed rows with the bottom row clicking forward after every letter (the
            Chaocipher shape, named for the click). A crib of a hundred letters breaks it outright; without
            one it wants a few thousand letters, because a short challenge text carries too little signal.
          • 
          
        • Foreign-language plaintext — French, German, Italian, Latin and Spanish models alongside English;
            pick one, or let Auto-detect probe all six.
          • 
          
        • Encodings and codes — base64/32/16/58/85, binary, URL, Morse, A1Z26, Polybius, Bacon, book ciphers.
          • 
          
        • Byte-level XOR — single byte and repeating key, over hex or base64 payloads.
          • 
          
        • Stacks of the above, in any order, up to the configured depth (six by default) — encodings wrapped around ciphers, and ciphers wrapped around ciphers.
          • 
        
        

        
        How it is built
        
        
        
          The core solver uses the Python standard library. No numpy, no requests, and no network access for solving.
          AES known-key operations use the optional maintained cryptography provider, bundled in the Windows installer.
          The web interface you are looking at is http.server and local static files; the search is
          the same engine the CLI runs, so python3 -m buttcrack "…" and this page give identical answers.
          Source and releases live on
          GitHub;
          the project also publishes a browser-only quick solver and a
          field guide to the classical ciphers
          — how to recognise each one by hand, and what actually breaks it.
        
        
        
        
          Command line: buttcrack <ciphertext>, identify, encrypt,
          decrypt, ciphers, demo, selftest, serve.
