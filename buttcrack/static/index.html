    Reading a report
    
        
    
          
    confidence
    How strongly the recovered text reads as English, tempered by how much evidence the ciphertext actually provided. ≥ 0.62 is reported as solved; ≥ 0.86 stops the search.
    
          
    path
    The decode chain, outermost layer first: base64 -> base16 -> xor_repeating.
    
          
    index of coincidence
    Probability that two random letters match. English ≈ 0.066, random ≈ 0.038, a transposition keeps it, a polyalphabetic cipher flattens it.
    
          
    quadgram fitness
    Log-probability per letter under a 258k-quadgram English model. Around −4.3 reads as English; below −6 does not.
    
          
    evidence cap
    A key that holds more secret than the ciphertext can pin down is capped below “solved”: plausible, not proven.
    
        
    
      
    
    
    
  
    

    



    
  
    
    
    
      
    
        
    What this is
    
        
    
          buttcrack is an automatic cipher breaker. Give it ciphertext and it works out what was
          used, recovers the key, and prints the plaintext — including puzzles where an encoding is wrapped
          around a cipher, or several layers deep.
        
    
        
    It runs three stages:
    
        
      
          
    1. Characterise. Length, alphabet, entropy, index of coincidence, chi-squared against
            English, structural tells (hex, base64, Morse, Bacon, Polybius, a Polybius grid, URL escapes).
      2. 
          
    2. Peel. Any strongly indicated encoding layer is stripped and the inside is attacked
            recursively, so base64 → hex → XOR is three easy problems rather than one hard one.
      3. 
          
    3. Attack. Each cipher has its own cryptanalysis: chi-squared column solving and
            quadgram hill climbing for Vigenère-family, coset-IC key-length detection plus per-byte solving for
            repeating-key XOR, simulated annealing and cycle walking for transpositions, an evidence-capped
            substitution solver.
      4. 
        
    
        
    
          Scoring uses an English model built from a 25-million-word corpus: quadgram
          statistics for fitness plus an 80,000-word dictionary for word coverage, blended differently on short
          texts where quadgrams are unreliable.
        
    

        
    What it will not do
    
        
    
          Modern cryptography is not a puzzle you can read your way out of. AES with a proper key, RSA, ChaCha20,
          elliptic curves: these have no letter statistics, no periodicity and no structure left to exploit, and
          brute force against a 128-bit key is not a matter of time. If your ciphertext is one of those, the honest
          answer is “this is not a classical cipher” — and that is what the detector will say.
        
    
        
    What it is genuinely good at:
    
        
      
          
    • Classical ciphers — Caesar, Vigenère and its variants, autokey, transpositions, Playfair, Bifid,
            substitution with a mixed alphabet.
      • 
          
    • Encodings and codes — base64/32/16/58/85, binary, URL, Morse, A1Z26, Polybius, Bacon, book ciphers.
      • 
          
    • Byte-level XOR — single byte and repeating key, over hex or base64 payloads.
      • 
          
    • Stacks of the above, in any order, up to the configured depth.
      • 
        
    

        
    How it is built
    
        
    
          Pure Python standard library. No numpy, no requests, no build step, no network access at runtime.
          The web interface you are looking at is http.server and three static files; the search is
          the same engine the CLI runs, so python3 -m buttcrack "…" and this page give identical answers.
        
    
        
    
          Command line: buttcrack <ciphertext>, identify, encrypt,
          decrypt, ciphers, demo, selftest, serve.
